# 任务卡规范

> 任务卡是**跨会话的唯一交接物**：新会话只读仓库（`AGENTS.md` → 本卡 → `START-HERE.md` → `doc/layers/**` → `git log -5`），不依赖聊天记录。
> 协作规则见 `AGENTS.md` §7；撰写要求见 `doc/05-engineering.md` §9。

## 1. 命名与位置

```text
doc/tasks/<里程碑>-<子任务>.md
```

例：`m10-b-deps.md`、`m10-closeout-job-stats.md`、`m11-1-yr-pack.md`。

## 2. 模板

```markdown
# MXX-Y：一句话目标

> 状态：规划中 / 进行中 / 已完成（日期 + 验证结果）
> 角色：规划 / 实现 / 验证（当前持有者）
> 最近更新：YYYY-MM-DD

## 1. 目标
一句话说明"做完能回答什么问题"。超过三句说明范围没切小。

## 2. 契约（用户定）
- 接口签名 / 数据布局 / 所有权 / 线程边界 / 失败语义
- 明确"不做"的边界

## 3. 文件所有权
- 用户手写：
- AI 实现（分步提交，用户 review）：
- AI 负责（测试 / CMake / 文档 / 机械替换）：

## 4. 测试与验收
- **用户先写的验收用例**（2~4 条：正常 / 失败 / 边界）：
  1. ...（防什么 bug）
- AI 补充（并发 / 预算 / 变异）：
- 验收命令与通过标准（debug / release / asan / tsan / format / deps）

## 5. 明确不做
（防止范围膨胀；想法进 `doc/02-roadmap.md` §S）

## 6. Q&A / 决策记录
- YYYY-MM-DD：结论 + 理由 + 被否决的替代方案

## 7. 交接块（每个工作单元结束时更新）
- 角色：规划 / 实现 / 验证
- 当前 HEAD：`<hash>`
- 工作区：干净 / 有未提交文件（列出，并说明是否红灯）
- 本单元完成：...
- 验证命令与结果：...
- 未决问题：...
- 下一步交给哪个角色：...
```

## 3. 规则

1. **一个会话一次只持有一张任务卡**；换卡先交接；
2. 状态只写三种：`规划中` / `进行中` / `已完成`；"基本完成"不算；
3. 决策回填到 §6，不要只留在聊天；
4. 红灯测试/脚手架不提交（`AGENTS.md` 红灯规则）；
5. 其他权威文档不重复任务卡内容：里程碑列表在 `02-roadmap.md`，当前任务指针在 `AGENTS.md` §2。
