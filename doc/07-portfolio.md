> 独立设计并实现了一个 C++20 游戏运行时（YRuntime）：从零实现句柄/反射/事件/场景树/序列化/异步资源/任务调度/主循环等模块，

## 2. 理解自检：怎么知道我"真的懂了"

**不要为了证明而做记录。** 判断标准只有一条：**能不能不看代码把它讲清楚。**

下面这张表是自检清单，不是产出要求——**绝大部分条目不需要落文件**。
它们对应 D17 的三个记录载体（commit message / ADR / checkbox），你只是在需要时确认自己答得出。

| 自检项 | 什么时候问自己 | 答案放哪 |
|---|---|---|
| **① 这个模块为什么存在？** 删掉它会怎样？ | 每个模块收口 | 头文件顶部的"为什么存在"注释 |
| **② 它和谁协作？边界在哪？** 谁拥有数据、谁只能读 | 写头文件之前 | 头文件契约注释 |
| **③ 失败模式是什么？** 传错句柄、跨线程调、资源没就绪会怎样 | 写测试之前 | 测试用例名字本身 |
| **④ 我的做法和 Godot 差在哪？为什么不同？** | 读完对照源码后 | 有架构影响 → ADR；没有 → 说完就忘 |
| **⑤ 哪个设计我后来推翻了？** 当时为什么会那么想？ | 里程碑收口 | ADR 的"已推翻"标记 |

**四个只做、不写的动作**（成本接近零，价值最高）：

1. **讲给 AI 听**：模块做完后，用 5 分钟把 ①~④ 讲一遍，让它挑漏洞。讲不下去 = 没懂，回去补（`05-engineering.md` §9.2 第 2 步）。
2. **commit message 写"为什么"**：这是唯一的高频记录载体，寄生在已有动作上（见 `START-HERE.md` §6）。
3. **对照阅读三段式**：Godot 怎么做 / 我怎么做 / 为什么不同（`04-godot-study.md` §1.1）。
4. **被卡住时先自己走一遍**：一句话描述问题 → 20 行最小复现 → `clang -E`/gdb/日志 → 读 Godot → 再问（`05-engineering.md` §9.3）。

> **诚实原则**：如果某个模块确实借助了 AI（比如 CMake 样板、CI yaml、Python 脚本），
> 在文件头或 commit message 里注明"AI 辅助生成，已逐行审查"。
> **`engine/` 下的核心实现代码必须自己写**（`05-engineering.md` §9.1 铁规则）。
> 一份标注清楚的作品比一份"看起来完美但说不清"的作品可信得多。

> **为什么删掉了原来的"证据链"四条**（2026-09-26）：
> 旧版要求 `notes/design/*.md` 时间戳早于代码、录讲解视频"留证"、以"至少 2 条 ADR 被推翻"为指标。
> 这三条分别违反 D17、把学习变成表演、把犯错变成 KPI（会诱导为了推翻而推翻）。
> 项目的目标是**理解**，不是**自证**；自证是理解的副产品，不能倒过来当驱动力。

## 5. 面试题库（40 题 + 好答案要点）

**用法**：每个里程碑收口时，把相关题目**自问自答一遍（口头即可，不必写下来）**。
**好答案的通用结构**：我做了什么 → 为什么这么做 → 备选是什么、为什么不选 → 遇到的具体问题与数据 → 如果重做会怎么改。
只背概念不给取舍 = 不及格。

### 对象模型与内存（M1~M2）
1. 为什么用 `index+generation` 句柄而不是裸指针或 `shared_ptr`？generation 位数怎么定？回绕了怎么办？
   *要点*：悬垂可检测、紧凑存储、cache 友好；`shared_ptr` 控制块分离且掩盖生命周期错误；回绕用 E1 数据 + 概率分析回答（结论：2^40 次复用不可达，接受）。
2. `SlotMap` 的删除为什么是 O(1)？稠密数组 + 空闲链的具体结构？删除后指针/迭代器失效怎么处理？
3. 侵入式引用计数与 `std::shared_ptr` 的差别？各自的代价？（*要点*：控制块、`sizeof`、侵入基类、跨模块 ABI）
4. 引用计数如何处理循环引用？你的 `WeakRef` 怎么实现？为什么 parent 指针不用 Ref？
5. 你的反射系统如何做到"新增一个类不改任何中心文件"？静态初始化顺序问题（SIOF）怎么解决？
6. 属性 get/set 的类型擦除具体怎么做的？为什么不用虚函数？三种擦除方案（成员指针+void* / `std::function` / 模板）的取舍？
7. 为什么自己写 Variant 而不用 `std::variant`？`sizeof(Variant)` 是多少，怎么算出来的？
8. 字符串驻留（StringId）解决了什么？哈希冲突怎么办？驻留表的内存与线程安全？

### 场景与生命周期（M3~M4）
9. 一个节点在自己的 `process` 里删除自己/父节点/兄弟节点，分别会发生什么？你怎么保证不崩？
   *要点*：`queue_free` + 阶段 9 统一 flush + 父子同删去重 + 遍历用双缓冲列表。这题最能区分"写过"和"读过"。
10. `_ready` 为什么是后序、`_process` 为什么是前序？如果反过来会出什么问题？
11. 事件总线的"立即派发"和"队列派发"你为什么两个都要？重入（回调里退订自己、回调里再发同一事件）怎么处理？
12. 如何保证"同样的输入两次运行产生逐字节相同的日志"？哪些地方会破坏确定性？
    *要点*：容器遍历顺序（保序 Dict）、浮点归约顺序、指针地址不入日志、并行任务结果顺序、时间源可注入。
13. 固定步长累加器怎么写？spiral of death 是什么、你怎么防？渲染插值为什么需要（可以只讲原理）？
14. 一帧里的 14 个阶段，为什么 `pump_assets` 在 `process` 之前而不是之后？为什么 GC 在最后？
15. Transform 层级的脏标记怎么传播？向上还是向下？多线程下会遇到什么问题？（附 E8 数据）

### 序列化与资源（M5~M6）
16. 你的场景格式如何处理"两个节点引用同一个资源"？外部资源与内嵌子资源的区别？
17. 循环引用（A→B→A）怎么序列化？为什么必须两遍法？
18. 老版本存档在新版本打不开，你的兼容策略是什么？未知属性和缺失属性分别怎么处理？
19. 为什么文本格式要求"输出逐字节可复现"？哪些实现细节会破坏它？（*要点*：保序容器、浮点格式化精度、时间戳/指针不入文件）
20. 二进制格式里结构体填充（padding）和字节序怎么处理？为什么不能直接 `fwrite(struct)`？
21. 资源为什么要 UID 而不只用路径？文件重命名/移动时发生了什么？
22. 异步加载的完整状态机？为什么解码可以在工作线程而对象构造必须回主线程？（D8）
23. 同一个资源被并发请求 5 次会发生什么？加载中被请求卸载呢？加载失败后 in-flight 条目怎么清理？
24. 资源什么时候卸载？refcount==1 的 GC 为什么会有"临时 Ref 导致本帧不卸载"的现象，这是 bug 吗？

### 并发（M7）
25. 你的任务依赖是怎么调度的？主线程在 `wait` 时做什么？为什么不能 sleep？
26. `memory_order_acquire/release` 在你的队列里具体保护什么？哪些地方可以用 relaxed，为什么？
27. false sharing 是什么？你在哪里遇到过、怎么发现的、怎么解决的？（附 E12 数据）
28. 并行化之后如何保证结果与串行一致？浮点求和为什么是个问题？
29. `~JobSystem()` 的停机流程？如果还有任务在跑、有任务在等待别的任务，怎么避免死锁？
30. TSan 报了一个你认为是误报的竞争，你怎么处理？（*要点*：先假设不是误报；suppress 文件要写理由）

### 渲染解耦与工程（M9~M11）
31. Runtime 与 Renderer 的边界你画在哪里？为什么是快照而不是接口回调？
32. 如果换成 OpenGL 后端，Runtime 需要改几行代码？你怎么**证明**这一点？（*要点*：CI grep 门禁 + NullBackend 跑全部测试 + 快照可重放）
33. Backend 里的 GPU 资源生命周期怎么管？Runtime 卸载资源时 GPU 侧正在用怎么办？
    *要点*：generation + frame-in-flight 延迟销毁（Yo_Renderer 的 `VulkanResourceTable` 已实践过，能讲清就是加分项）
34. 快照双缓冲/三缓冲的同步怎么做？Backend 落后 Runtime 两帧会怎样？
35. 你的 CMake 分层如何**物理上**阻止反向依赖？除了 CMake 还有什么机制？
36. 为什么禁用 `file(GLOB)`？为什么 `-Werror` 只在 CI 开？
37. CI 上无 GPU 怎么测渲染相关代码？
38. 项目里最难的一个 bug 是什么，你怎么定位的？（**要有真实故事**，能口述即可，见 `05-engineering.md` §9.3 的排查流程）
39. 哪个设计你做错了、后来推翻了？为什么当时会那么想？（**要有真实答案**，来自被推翻的 ADR）
40. 如果给你三个月继续做，你会先做什么？为什么？（考察优先级判断，答案要从 Stretch 清单里选并给理由）

## 8. 收口节奏（每个里程碑做什么，避免最后一周补救）

| 时机 | 动作 |
|---|---|
| 每个 M 收口 | 按 `02-roadmap.md` 的"里程碑收口 checklist"走（含 §2 的五个自检问题） |
| 每个 M 收口 | 存可运行物的录屏/截图 → 更新根 README 里程碑表 |
| 每 2~3 个 M | 想写博客就写（§4）；**写不出来说明还没懂，不是欠债** |
| M8 完成 | **第一个可运行节点**：文字冒险能玩 → 顺手更新简历条目初稿 |
| M10 完成 | **第二个可运行节点**：画面由 Runtime 驱动 → 架构图定稿、README 重写 |
| M11 完成 | 打磨：文档一致性、README 实测、简历终稿、§5 题库能自问自答 |

**关于公开**：仓库从第一天就 public，这样 commit 历史是自然形成的资产，不需要额外"留证"。
但注意——**公开是顺带的，不是目的**。不要为了"看起来像 8 个月的工作量"去凑 commit 数量；
小步提交的价值在于"出问题时能 bisect、能看清设计怎么演进"，那才是它真正的用处。
