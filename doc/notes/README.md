# notes/ · 过程记录

这里放**过程性**记录（与 `doc/` 根下的**规划性**文档相对）。四个子目录：

| 目录 | 内容 | 模板 / 规范 |
|---|---|---|
| `design/` | 每个模块的设计笔记（写代码**之前**建） | `_design-note-template.md` |
| `weekly/` | 周记，文件名 `YYYY-Wxx.md` | `_weekly-log-template.md` |
| `godot/` | Godot 源码对照笔记，文件名见 `04-godot-study.md` §3 的清单 | `04-godot-study.md` §1.1 的三段式格式 |
| `benchmarks/` | 实验报告（E1~E16，见 `03-learning-map.md` §4） | 问题 / 方法 / 数据表 / 结论 / **对设计的影响** |
| `evidence/` | 里程碑验收证据（测试输出、截图、CSV），按 `M0/`、`M4/` 分目录 | `02-roadmap.md` 收口 checklist |

**三条纪律**
1. 笔记是给自己看的，**但不能只有结论没有过程**。排查一个 bug 的完整路径，价值高于结论本身。
2. 每篇笔记必须能被 3 个月后的自己看懂：写清上下文、版本、日期。
3. 不复制粘贴未经消化的长文本（AI 生成、博客原文）。引用要给出处，结论要自己写。
