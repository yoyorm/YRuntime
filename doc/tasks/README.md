# 任务卡说明

> 任务卡只做两件事：**指明当前要推进的大致方向与问题边界**，以及**记录你讨论定下来的架构结论**。
> **不要**在任务卡里预先替用户写好头文件模板、结构体字段或二进制布局。

## 推荐结构

```markdown
# MXX-Y：模块方向名称

> 状态：讨论架构中 / 架构骨架编写中 / AI 填充细节与测试中 / 已完成
> 最近更新：YYYY-MM-DD

## 1. 推进方向与要解决的问题
- 这个模块在运行时里解决什么问题？
- 它和现有哪些模块/接口衔接？
- 明确不做什么（砍掉外围工程化膨胀）？

## 2. 架构讨论问题清单（供你思考与和 AI 探讨）
- 列出 2~4 个需要你自己决定架构方式的切入点（如数据怎么组织、职责放哪一层、生命周期/线程怎么管）。

## 3. 已确定的架构结论（讨论后填入）
- 记录你拍板的架构方案；随后由你编写头文件与架构骨架，再交给 AI 填充细节与测试。
```
